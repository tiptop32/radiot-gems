# Радио-Т: Находки

Курируемый каталог полезных тем из архива подкаста «Радио-Т». Каждая находка содержит категорию, уровень сложности, ссылку на официальный выпуск и точный таймкод.

- Репозиторий: <https://github.com/tiptop32/radiot-gems>
- Публикация: <https://tiptop32.github.io/radiot-gems/>

## Как запустить

```bash
npm install
npm run dev
```

Проверка перед публикацией:

```bash
npm test
npm run eval
npm run lint
npm run format:check
npm run build
```

## Структура

- `app/page.tsx` — страница: поиск, разделы, состояние каталога и плеера.
- `components/` — фильтры (`catalog-filters.tsx`), шкала годов
  (`year-dial.tsx`), таблица находок (`finds-table.tsx`) и нижний плеер
  (`player.tsx`).
- `hooks/use-audio-player.ts` — управление `<audio>`: старт с таймкода,
  пауза, перемотка, скорость, прогресс.
- `hooks/use-url-state.ts` — фильтры и выбранная находка живут в адресной
  строке, поэтому любой вид каталога можно отправить ссылкой.
- `hooks/use-listening.ts` и `lib/stored-value.ts` — прослушанные находки,
  место, где остановилось воспроизведение, и скорость; хранятся в
  `localStorage` этого браузера.
- `lib/catalog.js` — разделы, аудитории, фильтрация, сортировка, теги, годы,
  разбор и сборка URL; `lib/shownotes.js` — парсер шоунотов;
  `lib/timestamp.js` — таймкоды. Модули на JS, чтобы `node --test` проверял
  их без сборки.
- `scripts/shownotes.mjs` — подбор кандидатов и сверка каталога с шоунотами.
- `data/finds.json` — данные каталога.

## Публикация на GitHub Pages

Сайт публикуется как статический экспорт. Команда `npm run build:pages` собирает
его с переменной `GITHUB_PAGES=true`: vinext включается `output: 'export'`,
ставит `basePath: '/radiot-gems'` и `trailingSlash: true`, Cloudflare-плагин не
используется. Готовый загружаемый артефакт лежит в `dist/client/radiot-gems/` и обслуживается без
сервера: его корневая страница — `index.html`. Pages монтирует именно этот каталог
по адресу `/radiot-gems/`; загрузка родительского `dist/client/` добавит лишний
уровень и даст 404. В vinext beta.5 prerender мог не создать `index.html`, поэтому
используется beta.9 из lockfile и проверяется реальный артефакт. Обычная Cloudflare-сборка
(`npm run build`) при этом не меняется.

Публикация работает так:

1. Пуш в `main` запускает workflow `.github/workflows/pages.yml`.
2. Workflow прогоняет `npm test`, `npm run eval`, `npm run lint`,
   `npm run format:check`, собирает
   `npm run build:pages`, проверяет артефакт контрактом
   `tests/pages-artifact.test.mjs` и только потом загружает его.
3. Задача деплоя публикует артефакт через `actions/deploy-pages` со встроенным
   `GITHUB_TOKEN` — внешние секреты не нужны.
4. Pull request и ручной запуск (`workflow_dispatch`) собирают и проверяют сайт;
   деплой выполняется только для `main`.

После пуша ничего перезапускать не нужно: Pages отдаёт статику, обновление
появляется по окончании workflow.

Проверить сборку локально можно теми же командами:

```bash
npm run build:pages
npm run test:pages
npm run eval:pages
```

## Данные

Каталог находится в `data/finds.json`. Для каждой темы хранятся:

- номер выпуска и каноническая страница на `radio-t.com`;
- официальный MP3 на `cdn.radio-t.com`;
- текстовый таймкод и его значение в секундах;
- ссылка на материал из шоунотов (`sourceUrl`, может быть `null`);
- раздел (`section`): `dev`, `ai`, `infra`, `security`, `hardware`,
  `industry`, `career`;
- теги (`tags`) в нижнем регистре;
- аудитория (`audience`): `all` — для всех, `dev` — для разработчиков,
  `ops` — для инфраструктуры;
- короткое объяснение ценности темы.

Год выпуска берётся из адреса страницы выпуска.

### Как добавить находку

Шоуноты «Радио-Т» с таймкодами лежат в репозитории
[radio-t/radio-t-site](https://github.com/radio-t/radio-t-site)
(`hugo/content/posts/podcast-N.md`).

```bash
npm run finds:candidates -- 1020-1028   # черновики тем из выпусков 1020–1028
npm run finds:verify                    # сверить каталог с шоунотами
```

`candidates` печатает JSON с выпуском, таймкодом, страницей, MP3 и ссылкой на
материал — остаётся выбрать тему, дать ей `id`, раздел, теги, аудиторию и
написать пояснение. `verify` проверяет, что у каждой находки в шоунотах есть
тема с тем же таймкодом и той же ссылкой. Оба скрипта читают шоуноты с GitHub;
с `SHOWNOTES_DIR=path/to/hugo/content/posts` — из локальной копии.

Слушатели могут предложить тему через шаблон issue «Предложить находку».

### Воспроизведение

Страница выпуска «Радио-Т» не поддерживает запуск по таймкоду через URL. Поэтому основная кнопка использует встроенный плеер и устанавливает `currentTime`. Официальный таймкод остаётся источником данных, но воспроизведение начинается на 180 секунд раньше, чтобы не пропустить вводную часть разговора. Для тем в первые три минуты выпуск начинается с `00:00:00`.

Находка отмечается прослушанной, когда воспроизведение ушло на 5 минут дальше
её официального таймкода; отметку можно поставить и снять вручную. После
перезагрузки плеер возвращается на место, где остановился, на паузе.

Ссылка «MP3 с этого места» использует стандартный media fragment `#t=SECONDS` как запасной вариант. Его поддержка зависит от браузера.
